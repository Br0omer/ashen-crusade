# Pipeline V2 — Ashen Crusade

Кандидат: нужна реальная проверка в VS Code/OpenCode после merge; успешный CI не доказывает работу локального клиента.

## Роли и бюджет
| Роль | Модель | Задача |
| --- | --- | --- |
| Architect | GPT-6.2 Astra | Единый чат, план и координация |
| Game Designer | Gemini 4 Hydrogen | Механика, баланс, вопросы, дизайн-сводка |
| Developer | Claude Sonnet 5.5 | Код, тесты, локальный коммит |
| Git Operator | Gemini 4 Hydrogen | Только чтение status/CI/ревью |
| Reviewer + QA | Gemini из GitHub Actions | Независимый diff и игровая регрессия |

OpenRouter уже подключён; отдельные ключи для Designer/Git Operator не нужны. Цель расходов — до $100/мес.; фактическая стоимость зависит от токенов, изображения отдельно.

## Работа из одного чата
1. Architect для игровой идеи вызывает Designer и уточняет детали у тебя **в той же сессии**. Для технических багов сразу предлагает план.
2. Ты один раз утверждаешь цель, scope, критерии, тесты, создание ветки, коммит, push рабочей ветки и PR.
3. Architect вызывает только `node .opencode/scripts/git-flow.mjs start`: скрипт создаёт `feature/inc-YYYYMMDD-XXXXXXXX` от актуального main. Для первого ARCH-062 разрешён точный `start test/arch062-swap-fire`.
4. Developer создаёт `docs/increments/<тип>-<slug>.md` с `## Цель`, `## Критерии приёмки`, `## Проверки`; меняет только незапрещённые файлы и запускает `dev-flow.mjs status|check|commit` (только точные команды). Коммит остаётся локальным.
5. Architect проверяет результат и запускает `git-flow.mjs publish`. Скрипт проверяет защищённые пути и тесты, создаёт PR. `report` возвращает CI и актуальный вердикт Gemini. Владелец проводит ручную игровую приёмку и **только сам делает merge**.

## Границы
- Согласование в чате — процессный контроль, **не технический `ask`**: в текущем GUI он ненадёжен. Вместо него строгое разрешение конкретных команд без wildcard, проверки скриптов и ручной merge.
- Developer не изменяет `main`, принятые сборки, ART-02, root resources, `.github/`, `.opencode/` или секреты. Если задача требует защищённого файла — BLOCKED и отдельное согласование.
- Автотесты могут исполнять код рабочей ветки: не запускать недоверенные тесты; это не песочница. CI не заменяет проверку на Galaxy Tab S9+ с Xbox-геймпадом.
- Автоматические merge, force-push, rebase, удаление веток и локальные LLM запрещены.

## Первый сквозной тест
После merge обнови `main` через VS Code **Git: Pull** и открой новую сессию Architect. Попроси вызвать Designer из того же чата. Затем утверди регрессионный тест одновременного `RB+RT` для ARCH-062; писать только `tests/` и `docs/increments/`, **не менять `arch062/`**. Проверить путь до PR и Gemini; до этого Pipeline V2 остаётся непроверенным.
