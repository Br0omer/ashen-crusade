# Pipeline V2 — Ashen Crusade

Статус: кандидат. После merge нужна реальная проверка на MacBook в VS Code/OpenCode; CI не проверяет клиент.

## Роли
| Агент | Модель | Действие |
| --- | --- | --- |
| Architect (primary) | GPT-6.2 Astra | Единый чат, план, решение о делегировании, точные Git-команды |
| Game Designer | Gemini 4 Hydrogen (OpenRouter) | Уточнения механики и игровое ТЗ; только чтение |
| Developer | Claude Sonnet 5.5 (OpenRouter) | Код, ТЗ, тесты и локальный коммит |
| Git Operator | Gemini 4 Hydrogen (OpenRouter) | Читает status/CI/ревью |
| Reviewer + QA | Gemini через GitHub Actions | Независимый diff-review, регрессии, сценарии геймпада |

Без новых ключей: клиентские агенты используют существующее подключение OpenRouter; GitHub Actions — существующий `OPENROUTER_API_KEY`.

## Один инкремент — один чат Architect
1. Для игровых идей Architect подключает Game Designer, передаёт тебе его вопросы и предлагает варианты. Для обычного бага/теста сразу готовит технический план.
2. Ты **один раз** утверждаешь план (цель, критерии, границы, проверки) и разрешаешь ветку, реализацию, push ветки и PR.
3. Architect вызывает `node .opencode/scripts/git-flow.mjs start` без аргументов; создаётся новая `feature/inc-YYYYMMDD-XXXXXXXX`. Для ARCH-062 сохранена точная команда `start test/arch062-swap-fire`.
4. Developer в созданной ветке пишет `docs/increments/<тип>-<slug>.md` с разделами `## Цель`, `## Критерии приёмки`, `## Проверки`, реализует код вне защищённых файлов и вызывает только `dev-flow.mjs status|check|commit`. Скрипт валидирует ТЗ/пути, выполняет тесты и коммитит локально.
5. Architect оценивает результат, выполняет `git-flow.mjs publish`, затем `report`; ждёт CI и независимое ревью Gemini/QA.
6. Ты проверяешь игру на нужном устройстве и **лично** решаешь, делать ли merge.

## Безопасность и ограничения
- Организационное утверждение в чате **не равно техническому `ask`**; последнее в текущем GUI ненадёжно. Команды разрешены только по точным строкам, без wildcard shell, произвольных git/gh, склеивания команд и автоматического merge.
- Git-скрипты проверяют рабочую ветку, защищённые файлы и тесты; `main`, принятые сборки, ART-02 и секреты не менять. Developer не имеет права на `.github/`, `.opencode/` и защищённые сборки.
- Скрипты запускают локальный код тестов: это **не песочница** для недоверенного содержимого. При необходимости защищённых изменений — остановить инкремент, создать отдельный согласованный процесс.
- Художественная и игровая приёмка, включая Galaxy Tab S9+ с Xbox-геймпадом, остаётся за владельцем. Тесты и PR не означают принятие.

## Первая проверка после merge
В VS Code выполнить Git: Pull, создать **новую** сессию Architect; попросить его вызвать Game Designer в этой же беседе. Затем согласовать регрессионный тест одновременного `RB+RT` для ARCH-062: писать только `tests/` и `docs/increments/`, **не менять `arch062/`**. Проверить полный цикл до PR, CI и Gemini. До такого результата Pipeline V2 не считать проверенным.

## Бюджет
Цель — не более $100/мес. Astra только для сложных планов, Sonnet — код, Hydrogen — дизайнер и Git-чтение, Carbon — ревью после успешного CI. Стоимость зависит от фактических токенов; изображения считаются отдельно.
