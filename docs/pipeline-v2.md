# Pipeline V2 — один чат OpenCode

Кандидат. После merge требуется реальная проверка на MacBook в VS Code; CI не проверяет клиент OpenCode.

## Роли
- **Architect** (GPT-6.2 Astra): единая сессия, план, координация, PR.
- **Game Designer** (OpenRouter Gemini 4 Hydrogen): механики, вопросы, баланс, критерии; без записи файлов.
- **Developer** (Claude Sonnet 5.5): код, тесты, локальный коммит.
- **Git Operator** (Gemini Hydrogen): только чтение статуса и результатов PR.
- **Reviewer + QA** (Gemini в GitHub Actions): diff, регрессии, геймпад, ручные сценарии.

Работает с имеющимся OpenRouter и GitHub Secret. Новые ключи не нужны. Бюджет: цель до $100/мес., расходы зависят от токенов; изображения оплачиваются отдельно.

## Один инкремент
1. Для игровых задач Architect вызывает Designer и пересказывает его вопросы **в том же чате**. Для багов и тестов дизайнер необязателен.
2. Ты утверждаешь **один** план (цель, scope, критерии, проверки) вместе с разрешением создавать ветку, коммит, push рабочей ветки и PR.
3. Architect вызывает `git-flow.mjs start` без аргументов: создаётся уникальная `feature/inc-YYYYMMDD-XXXXXXXX` от актуального main. Для теста ARCH-062 доступна точная `start test/arch062-swap-fire`.
4. Developer пишет `docs/increments/<тип>-<slug>.md` с `## Цель`, `## Критерии приёмки`, `## Проверки`. Через `dev-flow.mjs status|check|commit` запускает проверки и создаёт локальный коммит.
5. Architect сверяет результат с планом, запускает `git-flow.mjs publish`, затем `report`. GitHub CI и Gemini проверяют PR. Владелец принимает игровой результат и **лично делает merge**.

## Границы
- Согласие в чате — организационное, **не системный `ask`**, который оказался ненадёжным в GUI. Shell разрешён только для точных команд; скрипты защищают файлы и не умеют merge.
- Developer не меняет принятые сборки, ART-02, root assets, `.github/`, `.opencode/`, секреты и main. Для защищённых изменений нужен отдельный согласованный процесс.
- Автотесты выполняют код локальной ветки, это не песочница для чужого кода. PASS CI не заменяет приёмку на Galaxy Tab S9+ с геймпадом.
- Только облачные LLM. Никакого автоматического merge, force-push, rebase, удаления веток.

## Первый сквозной тест
После merge: VS Code → **Git: Pull** → новая сессия Architect. Убедись, что дизайнер вызывается из той же беседы. Далее согласуй регрессионный тест `RB+RT` в одном тике ARCH-062; менять только `tests/` и `docs/increments/`, **не `arch062/`**. До успешного PR, CI и ревью Gemini интеграция Pipeline V2 не считается проверенной.
