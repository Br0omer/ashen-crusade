# ARCH-06 — расширяемое отображение персонажа

## ARCH-06.1: реализована, ожидает проверки на планшете
Кандидат: `1.1.0-arch061.1`, `/arch061/`. База — принятый статичный герой ART-01. Исходный коммит: `6b6d180e6d54c97eed40353b414ff89801f0afbf`.

Сборка автономна: содержит свои HTML, CSS, JS и изображения. Основная страница, ART-01, все предыдущие варианты ART-02 и контрольные сборки не изменены. Изображение героя побайтно совпадает с принятым ART-01. Спорная ходьба не подключена, сменное оружие не реализовано.

## Границы
- `js/character-visual.js`: реализация интерфейса CharacterVisual через `CharacterViews.StaticSpriteVisual`. Не читает игровые глобальные переменные, DOM, ввод, здоровье или урон; не управляет игровым циклом.
- `js/character-bridge.js`: перевод игрового состояния в снимок визуального состояния и выбор реализации. Здесь в ARCH-06.2 будет подключаться составной вариант.
- `js/hero-definition.js`: неизменяемые данные изображения, масштаба, опорной точки и ствола.
- `js/projection.js`: преобразование координат карты и изображения. `elevationPx` — экранное смещение по высоте, не физическая ось 3D.
- `gameplay.js`: перемещение, попадания, урон, время жизни пуль, враги и баланс. Не знает размер атласа и координаты ствола в картинке.

## Контракт CharacterVisual
`load()` возвращает Promise готовности ресурсов. Ошибка загрузки блокирует запуск, без скрытой подмены героя.

`preparePose(snapshot)` принимает root, velocity, aimAngle, time, locomotion, action, weaponId, muzzleFlash, hurtFlash. Рассчитывает неизменяемый снимок позы, не продвигает время анимации. Повторный расчёт в одном такте безопасен; будущая анимация должна использовать переданную фазу/время, а не число вызовов render.

`getSocket(name)` возвращает мировую точку `{x,y,elevationPx}` из последней подготовленной позы. Сейчас предусмотрены root и muzzle. До подготовки позы и для неизвестного имени выдаётся ошибка. Статичная реализация поддерживает только rifle-default; неподдерживаемое оружие не маскируется старой графикой.

`render(ctx, screenRoot)` только читает позу, не меняет её и не обновляет состояние игры. `getPose()` и `getStatus()` используются для диагностики и проверок.

## Порядок обновления
Ввод → таймеры и перемещение → решение о выстреле → preparePose → получение muzzle → создание снаряда → остальные игровые взаимодействия → повторная оценка позы для отображения полученного урона → render.

Вспышка и вылет пули используют одну позу и одну точку ствола. Снаряд сохраняет elevationPx, а отрисовка применяет его без знания устройства героя. Бой выполняется и без вызова render. Раскладка контроллера и числовые характеристики сохранены.

## Проверки
Локальный Chromium 144, код и изображения загружены из файлов с data-URI подстановкой ресурсов: сетевые переходы браузера среды ограничены. Контроллер имитирован программно, не физический Xbox.
- 7200 обновлений с одинаковым псевдослучайным вводом: 31 контрольный снимок игрового состояния совпал с ART-01, включая появление босса. Для длинной симуляции здоровье повышалось только в тестовом окружении.
- Отображение героя, отражения, мигания при уроне и вспышки: точное совпадение пикселей в четырёх проверенных позах.
- Ствол: совпадение координат с ART-01 на 34 направлениях; согласование экранной вспышки и мировой точки снаряда на 256 направлениях.
- Подстановка тестовой реализации с другим muzzle меняет точку выстрела без изменения боевой логики и без отрисовки.
- Пауза, повторный старт, стрельба, рывок, View/FPS и блокировка старта при ошибке ресурса проверены. Неожиданных ошибок JavaScript нет.
- `node tests/arch061-contract.cjs` — повторяемые проверки контракта без браузера. Подробный локальный результат: `tests/arch061-local-report.json`.

## Приёмка
На Galaxy Tab S9+ проверить: версия 1.1.0-arch061.1; статичный герой выглядит как ART-01; LS/RS, RT, B, Menu и View работают; пули и вспышка у ствола при движении и развороте; новых торможений нет. Отсутствие ходьбы на этом шаге намеренное.
