# Pipeline V2 — контекст каждого окна Gemini

## Цель
Исключить ложный BLOCKED при многооконном ревью: файлы и согласованное ТЗ PR должны быть известны каждому окну даже тогда, когда код отдельного файла ревьюится в другом окне.

## Критерии приёмки
- Каждому окну передаются полный список изменённых файлов PR и конкретный перечень файлов проверяемого окна.
- Полный текст изменённого согласованного ТЗ из docs/increments/ загружается отдельно и повторяется в каждом окне. Ошибка его получения — BLOCKED, а не скрытый пропуск.
- Ограничение размера diff и fail-closed агрегация остаются; ни одна строка патча не теряется.
- Gemini не считает отсутствие файла в частичном окне отсутствием файла во всём PR; подлинно недоступные необходимые данные и доказанные дефекты по-прежнему блокируют положительный вердикт.
- Код B1, принятые сборки, ключи, main не изменяются. Merge — только решение владельца.
