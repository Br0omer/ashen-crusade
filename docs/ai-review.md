# ARCH-07.3 — облачное независимое ревью без CodeRabbit

Вместо GitHub Marketplace используется GitHub Actions + OpenRouter. Локальных LLM нет; Mac mini и MacBook запускают только IDE/OpenCode/Git.

## Как настроить владельцу (один раз)

1. После проверки и merge инфраструктурного PR откройте **GitHub → Br0omer/ashen-crusade → Settings → Secrets and variables → Actions**.
2. Во вкладке **Secrets** создайте **New repository secret** с именем `OPENROUTER_API_KEY`. Значение — отдельный API-ключ из OpenRouter; никому не пересылайте его и не добавляйте в Git или комментарии.
3. Во вкладке **Variables** создайте **New repository variable** с именем `OPENROUTER_REVIEW_MODEL`. Вставьте актуальный идентификатор выбранной модели из каталога OpenRouter, которая поддерживает обычные текстовые chat completions. Подписки на сторонние PR-ревью и данные карты в GitHub Marketplace не нужны.
4. В GitHub → **Actions** убедитесь, что workflows включены. В Settings → Actions → General проверьте разрешение GitHub Actions создавать проверки и комментарии; рабочий процесс запрашивает `checks: write`, `pull-requests: write`, `contents: read`, `actions: read`.
5. Откройте/обновите PR из ветки **этого же репозитория** в `main`: `Contract tests` сначала проверит код, затем автоматически стартует `OpenRouter AI review`. Результат — комментарий бота и статус **OpenRouter AI review** на коммите PR. После исправлений и нового commit ревью повторится.

## Что проверяет ревьюер

- Читает GitHub PR (описание и критерии), реальный diff и доступные полные тексты изменённых небольших исходников, а также правила `AGENTS.md`, roadmap и release notes из доверенной ветки `main`.
- Только при успешном CI отправляет данные в облачную модель через OpenRouter; передаёт ей указание искать регрессии, опасные изменения принятых сборок, несоответствие задаче и пропущенные тесты.
- Пишет `PASS`, `CHANGES_REQUESTED` либо `BLOCKED`, перечень замечаний и проверки для владельца. Итог `PASS` означает **лишь автоматическое статическое ревью**; merge и художественную/игровую приёмку подтверждает владелец.
- При ошибке OpenRouter, неверном JSON, отсутствующем ключе/модели, проваленном CI, бинарных файлах или превышении лимита diff возвращает `BLOCKED`, не притворяется, что код проверен.

## Экономия и безопасность

- Один вызов модели на успешный CI в PR. При ошибках CI платный вызов не выполняется. Контекст: до 35 файлов/42 000 символов patch плюс ограниченные исходники и документация; общий бюджет генерации (рассуждение + ответ) ограничен 6500 токенами, с запросом низкой интенсивности рассуждения. Цена зависит от **выбранной модели** и объёма входных/выходных токенов в OpenRouter.
- Секрет доступен только GitHub Actions, код workflow запускается **исключительно из доверенной default branch**, PR-head никогда не checkout-ится и не выполняется. PR и изменённые файлы — недоверенные данные, передаваемые модели на чтение. Для безопасности и контроля расходов PR из forks и draft PR не обрабатываются.
- Автоматическая проверка не выполняет git push, не редактирует игровые файлы и не одобряет merge. Ключи не попадают в промпт; GitHub token используется только внутри скрипта для доступа к GitHub API.
- Большие/binary PR блокируются для ручной проверки; это особенно важно для визуальных ассетов. Проверка не заменяет просмотр игры на планшете.
- Если требуется повторить оценку **того же коммита** без нового push: GitHub → Actions → **OpenRouter AI review** → **Run workflow**, укажите номер PR и выберите `main`. При ручном запуске CI должен быть уже успешно выполнен на текущем PR.

## Примечания к запуску

Пока этот workflow находится только в **инфраструктурном PR**, `workflow_run` не будет запускать его из PR: GitHub использует конфигурацию из основной ветки. Реальный облачный запуск возможен **после merge**, создания Secret/Variable и следующего успешного PR CI. До этого валидируем только offline unit-тесты и существующие контракты.

GitHub branch protection при желании можно настроить дополнительно: сделать check `OpenRouter AI review` обязательным после проверки полного цикла. Не включайте его обязательным раньше, иначе новые PR могут блокироваться при ошибке подключения/провайдера.
